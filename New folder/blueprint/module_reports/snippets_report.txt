MODULE NAME: 
Ofast_X_Snippets (Code Snippets Manager)

PURPOSE:
Standalone snippet manager allowing admins to create, edit, and execute PHP, 
JavaScript, CSS, and HTML snippets that run on the WordPress site. Features 
include syntax validation, scope targeting, import/export, library templates, 
and revision history.

INTERNAL FUNCTIONS/CLASSES:

Key methods:

DATA FLOW:
1. Admin creates snippet via form with nonce protection
2. PHP code validated via token_get_all() and pattern matching
3. Snippet saved to wp_ofast_snippets database table
4. On init hook (priority 999), active snippets loaded from transient cache
5. If cache miss, query DB and set 1-hour transient
6. For each snippet: check scope, check page targeting, execute via eval()
7. Runtime errors caught via set_error_handler, snippet auto-deactivates
8. Audit log stored in options table (last 100 entries)

STEP 2: Modify ajax_delete_snippet() - Change to Soft Delete

REPLACE (lines 2078-2111):
    public function ajax_delete_snippet()
    {
        check_ajax_referer('ofast_snippet_delete', 'nonce');
        
        if (!current_user_can('manage_options')) {
            wp_send_json_error('Unauthorized');
        }
        
        if (!$this->check_rate_limit('delete')) {
            wp_send_json_error('Too many requests. Please wait a moment.');
        }
        
        $id = intval($_POST['id']);
        $permanent = isset($_POST['permanent']) && $_POST['permanent'] === 'true';
        
        global $wpdb;
        $table = $wpdb->prefix . 'ofast_snippets';
        
        $snippet = $wpdb->get_row($wpdb->prepare(
            "SELECT name, status FROM $table WHERE id = %d", $id
        ));
        
        if (!$snippet) {
            wp_send_json_error('Snippet not found');
        }
        
        if ($permanent && $snippet->status === 'trash') {
            // Permanent delete from trash
            $wpdb->delete($table, array('id' => $id));
            $this->log_snippet_action('PERMANENTLY_DELETED', $id, $snippet->name, '');
        } else {
            // Soft delete - move to trash
            $wpdb->update($table, array(
                'status' => 'trash',
                'active' => 0,
                'trashed_at' => current_time('mysql')
            ), array('id' => $id));
            $this->log_snippet_action('TRASHED', $id, $snippet->name, '');
        }
        
        $this->clear_snippets_cache();
        wp_send_json_success();
    }

    public function ajax_restore_snippet()
    {
        check_ajax_referer('ofast_snippet_restore', 'nonce');
        
        if (!current_user_can('manage_options')) {
            wp_send_json_error('Unauthorized');
        }
        
        $id = intval($_POST['id']);
        
        global $wpdb;
        $table = $wpdb->prefix . 'ofast_snippets';
        
        $snippet = $wpdb->get_row($wpdb->prepare(
            "SELECT name FROM $table WHERE id = %d AND status = 'trash'", $id
        ));
        
        if (!$snippet) {
            wp_send_json_error('Snippet not found in trash');
        }
        
        $wpdb->update($table, array(
            'status' => 'active',
            'trashed_at' => null
        ), array('id' => $id));
        
        $this->log_snippet_action('RESTORED', $id, $snippet->name, '');
        $this->clear_snippets_cache();
        
        wp_send_json_success();
    }

BACKEND HACKING RISKS & PREVENTION
================================================================================

QUESTION: Can this module be hacked even though it's admin-only/backend?
ANSWER: YES

Even with backend-only access, the module is vulnerable because eval() executes
ANY code that passes the blacklist validation.

--------------------------------------------------------------------------------
ATTACK VECTORS (How it can be hacked)
--------------------------------------------------------------------------------

1. COMPROMISED ADMIN ACCOUNT
   - Stolen credentials, session hijacking, password reuse
   - Once attacker has admin access, full code execution via eval()
   - Impact: Complete site takeover, database theft, malware injection

2. BLACKLIST BYPASS (Obfuscation)
   - Attackers can bypass function blacklist using:
     * String concatenation: $f='ev'.'al'; $f($code);
     * Variable variables: ${"exec"}("whoami");
     * Character codes: chr(101).chr(120).chr(101).chr(99) = "exec"
     * Base64 in variable: $x=base64_decode($encoded); $x();
   - Impact: Execute blocked functions despite validation

3. MALICIOUS IMPORT
   - Social engineering: "Install this snippet pack to fix X"
   - Malicious JSON file with obfuscated payload
   - Impact: Admin unknowingly imports backdoor

4. CSRF (Cross-Site Request Forgery)
   - If admin visits malicious site while logged in
   - Currently mitigated by nonces, but not impossible
   - Impact: Forced snippet creation/activation

5. INSIDER THREAT
   - Rogue employee with admin access
   - No audit trail for who approved what code
   - Impact: Untraceable backdoor installation

6. SUPPLY CHAIN (Template Library)
   - If library/snippets.json is compromised
   - Templates auto-imported without verification
   - Impact: Trusted templates become attack vector

--------------------------------------------------------------------------------
PREVENTION MEASURES (Recommended Implementation)
--------------------------------------------------------------------------------

IMMEDIATE (High Priority):
1. REMOVE EVAL() - Replace with action builder or hooks-only approach
2. ADD APPROVAL QUEUE - Snippet saved as "pending", second admin approves
3. ADD CODE LENGTH LIMIT - Maximum 1MB to prevent DoS
4. STRENGTHEN BLACKLIST - Add all obfuscation patterns

RECOMMENDED (Medium Priority):
5. REQUIRE 2FA FOR SNIPPET ACTIONS
   - Any create/edit/activate requires 2FA confirmation
   - Prevents compromised password exploitation

6. ADD CODE SIGNING FOR IMPORTS
   - Verify JSON imports have valid signature
   - Reject unsigned/modified imports

7. SUPER ADMIN ONLY (Multisite)
   - Restrict to is_super_admin() on multisite
   - Prevents site admins from affecting network

8. DETAILED AUDIT LOGGING
   - Log full code diffs, not just action name
   - Include IP, user agent, timestamp
   - Send email notification on snippet activation

9. SANDBOX TESTING
   - Execute new snippets in isolated environment first
   - Only activate if no errors/suspicious behavior

10. HASH VERIFICATION
    - Store hash of approved code
    - Detect if code modified after approval

OPTIONAL (Future Enhancement):
11. TIME-LIMITED SNIPPETS
    - Require re-approval after X days
12. WEBHOOK NOTIFICATIONS
    - Alert external monitoring on suspicious activity
13. RATE LIMITING PER IP
    - Not just per user, but per IP address

--------------------------------------------------------------------------------
REALISTIC RISK ASSESSMENT
--------------------------------------------------------------------------------

IF ATTACKER HAS ADMIN ACCESS:
- Without eval(): Can still damage site but limited to WP features
- With eval(): Complete server compromise possible

IF USING CURRENT MODULE AS-IS:
- Risk Level: HIGH for targeted attacks
- Risk Level: MEDIUM for opportunistic attacks (admin creds needed)

BOTTOM LINE:
The module is "secure" only as long as:
1. All admin accounts have strong unique passwords
2. No admin ever imports untrusted code
3. No admin clicks malicious links while logged in
4. No obfuscation patterns slip through blacklist

This is too many assumptions. eval() is inherently dangerous.
