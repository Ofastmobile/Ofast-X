=== BLOCKING ISSUES (WordPress.org) ===

1. SESSION USAGE WITHOUT JUSTIFICATION
   File: class-ofast-math-captcha.php
   Lines: 48-53, 153-156

   What is wrong:
   - Uses PHP sessions via session_start()
   - WordPress.org explicitly discourages session usage

   Code:
   ```php
   public function maybe_start_session() {
       if (session_status() === PHP_SESSION_NONE && !headers_sent()) {
           session_start();
       }
   }
   ```

   Why it is wrong:
   - Sessions break stateless architecture
   - Incompatible with many caching solutions
   - Can cause "headers already sent" errors
   - WordPress.org will flag this during review

   Real-world impact:
   - Plugin rejection on WordPress.org
   - Caching conflicts on production sites

   Blocks production: NO (has transient fallback), but BLOCKS WordPress.org submission

   RECOMMENDED FIX:
   Remove session usage entirely. The transient fallback at line 159 is already
   implemented and works correctly. Modify verify() to use only transient storage:

   ```php
   // Remove lines 48-53 (maybe_start_session method)
   // Remove lines 38-42 (session init hooks)
   // Remove session storage at lines 153-156
   // Remove session checks at lines 224-227, 251-253
   ```

=== WARNING ISSUES ===

1. MISSING NONCE CHECK IN SETTINGS SAVE
   File: class-ofast-turnstile.php
   Lines: 240-262

   What is wrong:
   - render_settings_form() processes $_POST and saves to database
   - Only checks current_user_can() but not nonce
   - Relies on parent form's nonce which may not be verified

   Code:
   ```php
   if (isset($_POST['turnstile_site_key']) && isset($_POST['turnstile_secret_key'])) {
       // Saves without explicit nonce verification
       update_option('ofast_turnstile_site_key', $site_key);
   }
   ```

   Why it matters:
   - Could be vulnerable to CSRF if called outside expected context

   RECOMMENDED FIX:
   Add explicit nonce check or remove save logic from render method,
   letting parent handle all saves:

   ```php
   // Option 1: Remove save logic from render_settings_form entirely
   // Save should be handled by parent form processor

   // Option 2: Add explicit nonce check
   if (isset($_POST['turnstile_site_key']) && 
       isset($_POST['_wpnonce']) && 
       wp_verify_nonce($_POST['_wpnonce'], 'ofast_spam_settings')) {
       // ... save logic
   }
   ```

2. EXTERNAL API CALL (TURNSTILE)
   File: class-ofast-turnstile.php
   Line: 127

   What is wrong:
   - Makes external HTTP request to challenges.cloudflare.com
   - WordPress.org requires disclosure of external service usage

   Code:
   ```php
   $response = wp_remote_post('https://challenges.cloudflare.com/turnstile/v0/siteverify', ...);
   ```

   Impact:
   - Must be disclosed in readme.txt under External Services section
   - User must provide keys (consent mechanism exists)

   Status: NOT BLOCKING if properly disclosed in readme.txt
