The SDK comes with a special mechanism to auto deactivate the free version when activating the paid one. In order for this mechanism to work properly, you'd need to slightly adjust the code of the plugin's main file. It should look like that:

<?php
    /**
     * Plugin Name: Ofast Toolkit
     * .....
     */

    if ( ! defined( 'ABSPATH' ) ) {
        exit;
    }

    if ( function_exists( 'ofast_x' ) ) {
        ofast_x()->set_basename( true, __FILE__ );
    } else {
        /**
         * DO NOT REMOVE THIS IF, IT IS ESSENTIAL FOR THE
         * `function_exists` CALL ABOVE TO PROPERLY WORK.
         */
        if ( ! function_exists( 'ofast_x' ) ) {

            // ... Freemius integration snippet ...

        }

        // ... Your plugin's main file logic ...
    }
?>
Using namespaces?
If you include the integration snippet outside the plugin's main file and that file is using a different namespace, since function_exists() is checking if the function exists relatively to the plugin main file's namespace, you'll need to include the namespace to the if condition as follows: if ( function_exists( '\Integration\Snippet\Namespace\ofast_x' ) ) {

Protecting paid logic from unauthorized use
If your plugin has a single paid plan, can_use_premium_code__premium_only() is the primary method you'll need to use to protect your paid features:

<?php
    // This entire code block will be remvoed from the free version.
    if ( ofast_x()->can_use_premium_code__premium_only() ) {

        // ... premium only logic ...

    }
?>

The code block will automatically be stripped from the free plugin version. Additionally, the logic within the if statement will only execute if the user is in a trial or has activated a valid license.

If your plugin has multiple plans offering different features, you can protect these features using is_plan():

<?php
    if ( ofast_x()->can_use_premium_code__premium_only() ) {
        if ( ofast_x()->is_plan( 'premium' ) ) {

            // ... logic related to the 'premium' plan and higher ...

        }

        if ( ofast_x()->is_plan( 'business' ) ) {

            // ... logic related to the 'business' plan and higher ...

        }
    }
?>

Adding contextual marketing and upsells
One effective technique to educate users about your paid features and increase conversion rates is to include contextual upsells. For example, you can add a setting for a paid feature (without implementing it), label it "Pro", and when the user interacts with it, inform them that it's a paid option and encourage them to upgrade.

To add logic that will execute only in the free codebase:

    echo '<label><input type="checkbox" name="pro-feature-1" />Pro Feature 1';
    if ( ! ofast_x()->is_premium() ) {
        // Adds a direct checkout link in the free version.
        echo sprintf( '<a href="%s"><small>Unlock Pro</small></a>', ofast_x()->checkout_url() );
    }
    echo '</label>';
To add logic that will execute only for non-paying users, even when running from the premium codebase:

<?php
    if ( ofast_x()->is_not_paying() ) {
        // Adds a marketing sections with a link to in-dashboard pricing page.
        echo '<section><h1>Awesome Features</h1>';
        echo sprintf( '<a href="%s">Upgrade Now!</a>', ofast_x()->get_upgrade_url() );
        echo '</section>';
    }
?>

(function($){

WordPress.org Compliance
According to WordPress.org guidelines, all code hosted on WordPress.org must be free and fully functional. Code with paid features cannot be served from WordPress.org.

Therefore, to deploy your free plugin's version to WordPress.org, ensure you wrap all premium code with if ( ofast_x()->is__premium_only() ) or the other methods  provided to exclude premium features and files from the free version.

Deployment
Ready to release a new version? Great! Zip your plugin's root folder and upload it in the Deployment section. Our PHP Processor will automatically generate two versions of your plugin:

Premium version: Identical to your uploaded version, including all code. Available for download only to your paying or trial customers.
Free version: Stripped of all paid features based on the licensing logic .
Assuming you've properly marked all paid logic and your plugin complies with WordPress.org guidelines, you can download the auto-generated free version from Freemius and upload it to WordPress.org.

Misc
WordPress core only supports a single static handler link to the uninstall hook using register_uninstall_hook() or by adding an uninstall.php file to your plugin's directory. Since Freemius tracks the uninstall event, using either of these methods will prevent the uninstall data, including user feedback, from being sent.

To resolve this, move the logic from uninstall.php to a function and delete the file. The goal is to have the uninstall logic in a function. Once ready, hook it to the Freemius uninstall action, which will execute after the uninstall event is reported to the server:

<?php
    // Not like register_uninstall_hook(), you do NOT have to use a static function.
    ofast_x()->add_action('after_uninstall', 'ofast_x_uninstall_cleanup');
?>
