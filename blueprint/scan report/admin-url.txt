ADMIN URL CUSTOMIZER - TECHNICAL DOCUMENTATION
MODULE NAME
Ofast X - Admin URL Customizer Module
===========================================================

PURPOSE
Security module that hides WordPress default login endpoints (/wp-admin, /wp-login.php) behind a custom secret URL to prevent brute force attacks, user enumeration, and unauthorized login attempts. Includes emergency bypass system, login attempt tracking, IP-based lockout, and email notifications.

modules/admin-url/class-ofast-admin-url-emergency.php (EMPTY FILE - UNUSED)

DATA FLOW
Settings Storage:
Options:
  - ofast_admin_custom_slug (string) - Custom login URL slug
  - ofast_admin_emergency_key (string) - 32-char emergency bypass key
  - ofast_admin_url_enabled (0|1) - Module enabled state
  - ofast_security_max_attempts (int, default: 5) - Max failed login attempts
  - ofast_security_lockout_duration (int, default: 15) - Lockout minutes
  - ofast_security_ip_whitelist (string) - Newline-separated IP list

Transients (per IP):
  - ofast_login_attempts_{md5(ip)} (int) - Failed attempt count
  - ofast_login_lockout_{md5(ip)} (timestamp) - Lockout start time
  - ofast_bypass_session_{md5(token)} (bool) - Emergency bypass session

Transients (hourly logs):
  - ofast_security_log_{YYYY-MM-DD-HH} (array) - Security events log

Cookies:
  - ofast_custom_login (value: 1, duration: 1 hour) - Custom URL access granted
  - ofast_admin_bypass (value: session_token, duration: 1 hour) - Emergency bypass session
Request Flow - Normal Login:
User accesses example.com/my-secret-login
handle_custom_url() detects slug match
Sets ofast_custom_login cookie (1 hour)
Redirects to wp-login.php
block_login_page() checks cookie, allows access
User logs in successfully
record_successful_login() clears lockout transients
Request Flow - Emergency Bypass:
User accesses wp-login.php?ofast_emergency={key}
init() checks emergency key with hash_equals()
If valid: Rotates key, sets session cookie, sends new key email
User has 1 hour to log in before session expires
Old key is now invalid (one-time use)
Request Flow - Lockout:
User fails login attempt
record_failed_login() increments ofast_login_attempts_{ip}
If attempts >= max_attempts: Set ofast_login_lockout_{ip} transient
send_security_alert() emails admin
Next login attempt: check_lockout_before_auth() returns WP_Error
User cannot authenticate until transient expires
Request Flow - Unauthorized Access:
User accesses /wp-admin or /wp-login.php without cookie
Not logged in, no cookie, no emergency key
block_login_page() or block_admin_pages() fires
Returns 404 template or wp_die()
SECURITY NOTES
CRITICAL VULNERABILITIES:
ISSUE 1: Cookie Hijacking - No Secure/HttpOnly Flags Verification Lines 75, 90, 116 use setcookie() without verifying HTTPS context.

php
setcookie('ofast_admin_bypass', $session_token, time() + 3600, COOKIEPATH, COOKIE_DOMAIN, is_ssl(), true);
PROBLEM: If is_ssl() returns false on HTTPS site (misconfigured server), cookie sent over HTTP = interceptable.

FIX: Force secure flag on production:

php
$secure = (is_ssl() || (isset($_SERVER['HTTP_X_FORWARDED_PROTO']) && $_SERVER['HTTP_X_FORWARDED_PROTO'] === 'https'));
setcookie('ofast_admin_bypass', $session_token, time() + 3600, COOKIEPATH, COOKIE_DOMAIN, $secure, true);
ISSUE 2: Timing Attack on Emergency Key (MITIGATED) Line 71 uses hash_equals() - CORRECT implementation. No issue here.

ISSUE 3: Session Token Not Cryptographically Random Line 73:

php
$session_token = wp_generate_password(32, false);
wp_generate_password() uses rand() which is NOT cryptographically secure.

FIX:

php
$session_token = bin2hex(random_bytes(32));
ISSUE 4: Emergency Key Stored in Plain Text Emergency key stored in wp_options without encryption. If database is compromised, attacker has bypass key.

RECOMMENDATION: Encrypt key at rest:

php
$encrypted_key = openssl_encrypt($emergency_key, 'AES-256-CBC', AUTH_KEY, 0, substr(md5(AUTH_SALT), 0, 16));
update_option('ofast_admin_emergency_key', $encrypted_key);
ISSUE 5: IP Spoofing via X-Forwarded-For Lines 579-583:

php
if (!empty($_SERVER['HTTP_X_FORWARDED_FOR'])) {
    $ip = explode(',', $_SERVER['HTTP_X_FORWARDED_FOR'])[0];
}
PROBLEM: X-Forwarded-For is user-controllable. Attacker can bypass lockout by setting header.

FIX: Only trust X-Forwarded-For if behind known proxy:

php
$trusted_proxies = array('127.0.0.1', '::1'); // Add your proxy IPs
if (in_array($_SERVER['REMOTE_ADDR'], $trusted_proxies) && !empty($_SERVER['HTTP_X_FORWARDED_FOR'])) {
    $ip = explode(',', $_SERVER['HTTP_X_FORWARDED_FOR'])[0];
} else {
    $ip = $_SERVER['REMOTE_ADDR'];
}
ISSUE 6: No CSRF Protection on Delete Action Line 134-141: Delete custom URL uses nonce but doesn't check referer.

RECOMMENDATION: Add referer check:

php
check_admin_referer('ofast_admin_url_save', '_wpnonce');
if (!wp_verify_nonce($_POST['_wpnonce'], 'ofast_admin_url_save') || !check_admin_referer('ofast_admin_url_save', '_wpnonce')) {
    wp_die('Security check failed');
}
ISSUE 7: Insufficient Emergency Key Entropy Line 74, 170, 343:

php
$emergency_key = wp_generate_password(32, false);
Only alphanumeric (62 chars^32) ≈ 190 bits entropy. Good, but not using special chars.

RECOMMENDATION: Use full entropy:

php
$emergency_key = wp_generate_password(32, true, true); // Include special chars

FIX: Validate admin email:

$admin_email = get_option('admin_email');
if (!is_email($admin_email)) {
    return; // Don't send if invalid
}

FIX: Add rate limiting:

if (isset($_GET['ofast_emergency'])) {

    if ($attempts >= 5) {

    }
    set_transient($attempt_key, $attempts + 1, MINUTE_IN_SECONDS);
    // ... rest of emergency key validation
}

PERFORMANCE NOTES
CRITICAL PERFORMANCE ISSUES:
ISSUE 1: Database Write on Every Failed Login Lines 504-507:

php
set_transient('ofast_login_attempts_' . md5($ip), $attempts, $lockout_duration * MINUTE_IN_SECONDS);
IMPACT: Each failed login writes to wp_options table. On shared hosting with 1000 brute force attempts/hour, this causes table lock contention.

FIX: Use object cache if available:

php
if (function_exists('wp_cache_set')) {
    wp_cache_set('ofast_login_attempts_' . md5($ip), $attempts, 'ofast_security', $lockout_duration * MINUTE_IN_SECONDS);
} else {
    set_transient('ofast_login_attempts_' . md5($ip), $attempts, $lockout_duration * MINUTE_IN_SECONDS);
}
ISSUE 2: Regex on Every Request Lines 109, 113, 176:

php
if (strpos($request_uri, '/wp-admin') === false) {
    return;
}
IMPACT: String operations on every template_redirect. Negligible but could be optimized.

FIX: Cache result:

php
static $is_admin_request = null;
if ($is_admin_request === null) {
    $is_admin_request = (strpos($_SERVER['REQUEST_URI'], '/wp-admin') !== false);
}
if (!$is_admin_request) {
    return;
}
ISSUE 3: Multiple Transient Reads Per Request Lines 475-478, 485-488: Each request may call get_transient() multiple times for same IP.

FIX: Cache in class property:

php
private $ip_cache = array();

private function is_ip_locked_out($ip) {
    if (!isset($this->ip_cache[$ip])) {
        $this->ip_cache[$ip] = get_transient('ofast_login_lockout_' . md5($ip));
    }
    return (bool) $this->ip_cache[$ip];
}
ISSUE 4: Security Log Unbounded Growth Lines 593-606: Logs stored in hourly transients with 24-hour expiry. On high-traffic site with 10,000 events/hour, this could be 50KB+ per transient × 24 hours = 1.2MB in wp_options.

FIX: Add max events per hour AND shorter expiry:

php
if (count($log) >= 50) {
    $log = array_slice($log, -49); // Already implemented - GOOD
}
set_transient($log_key, $log, HOUR_IN_SECONDS * 2); // Reduce from 24 hours to 2 hours
ISSUE 5: Email Sent on Every Lockout Line 520: send_security_alert() called on every max attempt lockout. If attacker triggers 100 lockouts/hour from different IPs, admin gets 100 emails.

FIX: Rate limit alert emails:

php
$alert_key = 'ofast_last_alert_' . md5($ip);
if (!get_transient($alert_key)) {
    $this->send_security_alert($ip, $username, $attempts);
    set_transient($alert_key, time(), HOUR_IN_SECONDS); // Max 1 alert per IP per hour
}
ISSUE 6: parse_url() on Every Request Line 107:

php
$request_uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
IMPACT: Minor overhead on every init hook.

FIX: Use explode:

php
$request_uri = explode('?', $_SERVER['REQUEST_URI'])[0];
ISSUE 7: No Object Cache Invalidation If using persistent object cache (Redis/Memcached), lockout data persists even after admin clears it from database.

FIX: Use cache groups or manual invalidation:

php
wp_cache_delete('ofast_login_attempts_' . md5($ip), 'ofast_security');

LOOPHOLES:
LOOPHOLE 1: Admin Can Lock Themselves Out If admin changes custom slug, forgets it, and doesn't receive email (spam filter, typo, server issue), they're locked out.

MITIGATION: Already implemented with OFAST_DISABLE_ADMIN_PROTECTION constant - GOOD.

LOOPHOLE 2: Shared IP Lockout Users behind NAT/corporate firewall share IP. One user's failed attempts lock out entire office.

MITIGATION: IP whitelist feature implemented - GOOD. Should document this prominently.

LOOPHOLE 3: Custom Slug Collision If custom slug matches existing page/post slug (e.g., user creates page /secret-login), WordPress routing takes precedence, custom login breaks.

FIX: Add slug validation:

php
$existing_post = get_page_by_path($new_slug);
if ($existing_post) {
    add_settings_error('ofast_admin_url', 'collision', 'That URL already exists as a page/post. Please choose another.', 'error');
    return;
}

// Clear URL from history after use

LOOPHOLE 5: Cookie Not Cleared on Logout ofast_custom_login cookie persists after logout. User could access login page for up to 1 hour after logout.

add_action('wp_logout', array($this, 'clear_login_cookie'));
