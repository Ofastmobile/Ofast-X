5. VULNERABILITIES (CRITICAL)
SECURITY BLOCKING ISSUES:
A. SQL INJECTION - CRITICAL

What: Direct SQL concatenation in queue cleanup
Where: Scheduler class line 93
php
  $wpdb->query($wpdb->prepare(
      "DELETE FROM {$wpdb->prefix}ofast_email_logs WHERE sent_at < %s",
      $delete_before
  ));
```
- **Problem:** `$wpdb->prefix` is RAW, not escaped
- **Exploitation:** If WordPress allows table prefix modification mid-runtime (rare but possible), attacker controls DELETE target
- **Severity:** HIGH (data loss)
- **Fix Required:** Use `$wpdb->prefix` only after validation or use `$wpdb->tablename` constant

**B. STORED XSS - CRITICAL**
- **What:** Email body saved to database without sanitization, output without escaping
- **Where:** 
  - Save: Line 240 (admin) - `wp_kses_post()` allows iframes, scripts
  - Output: Line 479 (history) - `esc_attr(base64_encode($log->body))` doesn't prevent XSS in iframe srcdoc
- **Attack Vector:**
```
  1. Admin saves email with: <img src=x onerror=alert(document.cookie)>
  2. Victim admin clicks "Preview" in history
  3. JavaScript executes in admin context
```
- **Impact:** Session hijacking, privilege escalation
- **Severity:** CRITICAL

**C. CSRF - MEDIUM**
- **What:** Queue actions (pause/resume/delete) use GET requests with nonces
- **Where:** Line 67-98 (queue admin)
- **Problem:** Nonces in GET URLs are logged in:
  - Browser history
  - Server access logs
  - Referrer headers
- **Attack:** Attacker tricks admin into visiting:
```
  /wp-admin/?page=ofast-emailer&tab=queue&action=delete&batch_id=5&_wpnonce=abc123
Impact: Unauthorized batch deletion
WordPress Standard: Use POST for state-changing actions
